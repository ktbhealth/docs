[Drizzle Studio](https://orm.drizzle.team/drizzle-studio/overview) is a local
graphical browser for the database — tables, columns, relations, and rows.
Use it to explore the schema or inspect data while developing.

## Open Studio

```bash
bun run db:studio        # from the product repo root
```

The command materializes `packages/db/.studio.sqlite` — a local SQLite file
built by applying every Drizzle migration — and opens Studio against it at
`localhost:4983` (or the port Studio prints).

The file is gitignored and disposable: it is rebuilt automatically whenever
a migration is newer than the file. It is **not** your dev D1 database —
it starts empty (schema only, no rows) and is meant for inspection, not for
the running app.

## What to look at

- **Tables** — every table from every plugin, grouped by the schema they
  belong to. Cross-reference with the
  [generated table reference](/en/docs/developers/plugins) (ER diagrams +
  per-table columns/indexes).
- **Relations** — foreign keys appear as Studio relations, matching the
  `erDiagram` in each plugin's reference section.
- **Rows** — the studio DB has no application data. To see real data, use
  the app's local D1 (miniflare) state or seed the studio DB manually.

## When Studio is not enough

- Schema *changes* start in `packages/db/src/schema.ts` → `bun run
  db:generate` — see [database migrations](/en/docs/developers/kernel/how-to/migrations).
- Published schema docs (ER diagrams, per-table reference, pt-BR) are
  generated by `bun run db:erd` — they live under each plugin's
  `reference/` section, not in Studio.
