`apps/web` deploys as a single **Cloudflare Worker** provisioned by
**Alchemy** (`apps/web/alchemy.run.ts`). Infrastructure is code — the stack
declares resources and bindings; there is no manual dashboard setup.

## Resources

| Resource      | Purpose                                              | Defined in            |
| ------------- | ---------------------------------------------------- | --------------------- |
| D1 database   | All app data (`DB` binding)                          | `deploySqlDatabase`   |
| Workers AI    | `AI` binding — transcription/LLM features            | `Cloudflare.Workers.AI()` |
| R2 bucket     | Consultation audio (`AUDIO_BUCKET`, private)         | `Cloudflare.R2.Bucket("audio")` |
| Queue         | Async transcription (`AUDIO_QUEUE` → same worker)    | `Cloudflare.Queues.Queue("transcription")` |

Migrations for D1 are generated by Drizzle (`bun run db:generate`) and
synced into `packages/db/alchemy-migrations` at deploy time
(`sync-alchemy-migrations.mjs`, run inside `infra:deploy`).

## Bindings and secrets

Everything the worker needs arrives as a **binding**, not a build-time
constant:

- Secrets (`BETTER_AUTH_SECRET`, `TURNSTILE_SECRET_KEY`, LLM keys,
  `RECALL_API_KEY`, …) are injected by `cuora run --env prod` at deploy
  time — see
  [Environment variables](/en/docs/developers/root/how-to/environment-variables).
- Non-secret config (`BETTER_AUTH_URL`, `PLATFORM_ADMIN_EMAILS`,
  `VITE_DOCS_URL`) is bound the same way for parity.

This is why arch rules ban `process.env`/`cloudflare:*` outside the edge:
plugins receive capabilities through Effect services, never through env
reads.

## Deploy

```bash
cd apps/web && bun run infra:deploy   # sync migrations → cuora → alchemy deploy --stage prod
```

Requires cuora vault access. Stages map to Alchemy stages; `prod` is the
live environment.

## Local vs production runtime

`bun run dev` runs the real **workerd** runtime via miniflare — bindings,
D1, and `.dev.vars` behave like production. `bun run dev:node` is a plain
Node path for faster iteration; it re-implements binding shims in
`src/lib/`. Prefer `dev` when debugging anything binding-related.
