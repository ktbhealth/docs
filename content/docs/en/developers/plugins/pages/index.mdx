The pages plugin serves custom pages: rows in `pages` rendered on demand
at normalized URL paths, managed through the admin surface — no deploy
needed to publish content. The page body is not stored on the row: it
references a `rich_text` document, a `layouts` composition, or a
site-builder `builder_json` document.

## Key concepts

- **Content as data** — `path`, `title`, `published`, `showInNav`,
  `sortOrder`, plus `richTextId`/`layoutId`/`builderJson`/
  `searchSchemaId` references to the body, layout, builder document, and
  URL-param schema.
- **Path normalization** — `normalizePagePath` is the single validator for
  admin input and request paths; it rejects the `/platform` namespace so
  custom pages can never shadow the admin console.
- **Invisible drafts** — only `published` rows render; drafts 404 for
  visitors rather than 403.
- **Nav contribution** — `showInNav` + `sortOrder` feed the site
  navigation via `chrome.tsx`.
