`plugins/groups` is the generic grouping primitive: `groups` rows
(clinics, orgs, cohorts — `kind` is free-form, `meta` is a JSON payload)
plus `group_members`, a polymorphic membership table
(`memberKind`/`memberId`, `"user"` today). It is also the **tenant
primitive**: `patients.tenant_id` and `consultations.tenant_id` point at
`groups.id`, so membership here is what makes a row visible to a clinic's
members.

## Concepts

- **Group** — `name`, unique `slug`, `kind`, optional `meta` JSON.
- **Member** — `(groupId, memberKind, memberId, role?)`; one row per
  member, cascade-deleted with the group.
- **Tenant link** — services resolve the caller's accessible tenant set
  via `@ktb/tenant` (`accessibleTenantIds`, `tenantScopeCondition`); a
  `tenant_id` of `NULL` means a personal row, a `groups.id` means
  tenant-owned.

## Add membership in code

Membership writes go through the plugin's services (`GroupsLive` /
`GroupsQueriesLive` in `plugins/groups/src/index.ts`) — the same
CQRS-style layers other plugins use. From another plugin, dispatch the
group queries via the `Query` service rather than importing tables:

```ts
const groups = yield* Query.dispatcher(GroupsQueries);
const result = yield* groups["groups.list"]({ /* … */ });
```

(Check `plugins/groups/src/api.ts` for the exact query names.)

## Add a new member kind

`memberKind` is a free-form text column — `"user"` is the only kind in use
today, `"patient"` is planned. To support a new kind:

1. Keep `memberId` as text (ids are strings across the schema).
2. Add the kind's resolution logic in the service layer — who is allowed
   to add/remove that kind of member is an authz decision.
3. If the kind affects tenant visibility, extend
   `accessibleTenantIds`/`tenantScopeCondition` usage in `@ktb/tenant` —
   do not special-case it inside consumers.

## Schema changes

`groups`/`group_members` are plugin-owned tables aggregated by the
generated `schema.gen.ts`. Changes follow the standard flow:
`schema.ts` → `bun run db:generate` → `bun run db:migrate:local` →
`bun run db:erd`.

See the [groups table reference](/en/docs/developers/plugins/groups/reference)
for the generated column/index docs.
