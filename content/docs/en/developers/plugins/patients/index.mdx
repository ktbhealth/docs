The patients plugin owns the patient record: the `patients` table, CQRS
commands/queries, record validation, and the consult linkage other plugins
consume.

## Key concepts

- **FHIR R4 alignment** — fields map to FHIR Patient + RNDS/BR Core
  extensions; everything beyond `name` is nullable so minimal records stay
  valid. Codes and labels live in `record.ts`.
- **Dual scoping** — `owner_id` (personal rows) + `tenant_id` → `groups.id`
  (clinic-owned rows), fenced by `patientScope`/`tenantScopeCondition`.
- **CQRS surface** — `PatientsQueries`/`PatientsCommands` on the `EventBus`;
  other plugins dispatch `patients.ownerOf` etc. instead of joining tables.
- **Events** — `PatientCreated`/`PatientDeleted` feed notifications and
  audit.
