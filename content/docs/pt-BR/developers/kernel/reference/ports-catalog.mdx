O código de domínio fala com **ports** — interfaces nomeadas por capacidade, não
por fornecedor. Adapters na borda os implementam. Este é o catálogo atual.

| Port | Vive em | Capacidade | Adapters atuais |
| ---- | ------- | ---------- | --------------- |
| `Transcriber` | `packages/transcription` | Speech-to-text no cliente (eventos partial/final, estatísticas de confiança, captura de áudio) | `@ktb/transcription-whisper` (Whisper worker no navegador), `@ktb/transcription-webspeech` (Web Speech API) |
| Engine de transcrição | `packages/transcription` (port de engine) | Backend ASR no servidor | whisper-large-v3-turbo via Workers AI (`@cf/*` — literal apenas em adapter) |
| `Db` | `packages/db` | Acesso a banco de dados (Drizzle) | Cloudflare D1 (prod/dev), `@ktb/db-sqlite` better-sqlite3 (`dev:node`) |
| Armazenamento de áudio | pipeline de consultations | Blob storage de áudio de sessão | Cloudflare R2 (`audioKey`) |
| Captcha | `packages/captcha*` | Proteção contra bots | Turnstile (`captcha-turnstile`), stub local (`captcha-stub`) |
| Auth | `packages/auth*` | Sessões/identidade | better-auth (`auth-better`) |
| Interop | `packages/interop-*` | Troca de dados com EHR | FHIR, openEHR (em andamento) |

## Convenções

- Pacotes de port contêm **apenas interfaces e tipos de domínio** — sem imports
  de vendors, sem `node:*`/`Bun`/`process`, sem literais de provider.
- Adapters são pacotes irmãos (`<capability>-<vendor>`) selecionados na
  composition root.
- Nova capacidade? Adicione um port num pacote de domínio em `packages/`
  primeiro, depois os adapters. Veja o tutorial
  [Adicionar um adapter de port](/pt-BR/docs/developers/kernel/tutorials/add-a-port-adapter).
